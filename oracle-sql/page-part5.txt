e></td><td>같은 부서 직원들의 급여를 다시 조회</td></tr>
<tr><td><code>E2.DEPARTMENT_ID = E.DEPARTMENT_ID</code></td><td>현재 직원과 같은 부서만 비교</td></tr>
<tr><td><code>MAX(E2.SALARY)</code></td><td>그 부서 최고 급여 1개</td></tr>
<tr><td><code>E.SALARY = (...)</code></td><td>현재 직원 급여가 최고 급여와 같으면 출력</td></tr>
</table>

<h3>9. 실습 — 자기 부서 평균보다 많이 받는 직원</h3>
<pre><button class="copy">복사</button><code>SELECT E.LAST_NAME,
       D.DEPARTMENT_NAME,
       E.SALARY
FROM EMPLOYEES E, DEPARTMENTS D
WHERE E.DEPARTMENT_ID = D.DEPARTMENT_ID
AND E.SALARY &gt; (
    SELECT AVG(E2.SALARY)
    FROM EMPLOYEES E2
    WHERE E2.DEPARTMENT_ID = E.DEPARTMENT_ID
);</code></pre>

<div class="danger"><b>왜 여기에는 GROUP BY가 없을까?</b><br>
안쪽 SELECT의 <code>WHERE E2.DEPARTMENT_ID = E.DEPARTMENT_ID</code>가 이미 <b>현재 직원과 같은 한 부서</b>만 골라냅니다.
그 한 부서의 급여들을 <code>AVG()</code>로 평균 내면 결과는 1개입니다.
따라서 여러 부서를 각각 묶어 평균을 계산하는 GROUP BY가 필요하지 않습니다.</div>

<table>
<tr><th>헷갈리는 생각</th><th>정리</th></tr>
<tr><td>AVG가 있으니까 GROUP BY?</td><td>아님. AVG는 GROUP BY 없이도 사용 가능</td></tr>
<tr><td>“부서 평균”이니까 GROUP BY?</td><td>여러 부서를 한꺼번에 각각 계산할 때는 필요하지만, 여기서는 WHERE가 현재 한 부서로 좁힘</td></tr>
<tr><td>현재 직원의 부서를 어떻게 안쪽에 전달?</td><td><code>E2.DEPARTMENT_ID = E.DEPARTMENT_ID</code></td></tr>
</table>

<h3>10. 실습 — 부서별 평균 이상 직원 수</h3>
<pre><button class="copy">복사</button><code>SELECT D.DEPARTMENT_NAME,
       COUNT(*) AS 직원수
FROM EMPLOYEES E, DEPARTMENTS D
WHERE E.DEPARTMENT_ID = D.DEPARTMENT_ID
AND E.SALARY &gt;= (
    SELECT AVG(E2.SALARY)
    FROM EMPLOYEES E2
    WHERE E2.DEPARTMENT_ID = E.DEPARTMENT_ID
)
GROUP BY D.DEPARTMENT_NAME;</code></pre>

<table>
<tr><th>순서</th><th>하는 일</th></tr>
<tr><td>1</td><td>EMPLOYEES와 DEPARTMENTS JOIN</td></tr>
<tr><td>2</td><td>각 직원마다 자기 부서 평균 급여 계산</td></tr>
<tr><td>3</td><td>평균 이상 직원만 WHERE에서 남김</td></tr>
<tr><td>4</td><td>남은 직원을 부서 이름으로 GROUP BY</td></tr>
<tr><td>5</td><td><code>COUNT(*)</code>로 부서별 직원 수 계산</td></tr>
</table>

<h3>11. 실습 — 평균 급여가 7000 이상인 부서의 직원</h3>
<pre><button class="copy">복사</button><code>SELECT E.LAST_NAME,
       D.DEPARTMENT_NAME,
       E.SALARY
FROM EMPLOYEES E, DEPARTMENTS D
WHERE E.DEPARTMENT_ID = D.DEPARTMENT_ID
AND E.DEPARTMENT_ID IN (
    SELECT DEPARTMENT_ID
    FROM EMPLOYEES
    WHERE DEPARTMENT_ID IS NOT NULL
    GROUP BY DEPARTMENT_ID
    HAVING AVG(SALARY) &gt;= 7000
);</code></pre>

<table>
<tr><th>부분</th><th>이유</th></tr>
<tr><td><code>GROUP BY DEPARTMENT_ID</code></td><td>부서별 평균을 각각 계산</td></tr>
<tr><td><code>HAVING AVG(SALARY) &gt;= 7000</code></td><td>집계된 부서 평균에 조건</td></tr>
<tr><td>안쪽 결과</td><td>조건을 만족하는 부서ID가 여러 개일 수 있음</td></tr>
<tr><td><code>IN</code></td><td>여러 부서ID 중 하나에 속하는지 확인</td></tr>
</table>

<h3>12. 단일행 / 다중행 빠른 판별표</h3>
<table>
<tr><th>안쪽 SELECT</th><th>결과</th><th>판단</th></tr>
<tr><td>찬희의 점수 조회</td><td>1개</td><td>단일행</td></tr>
<tr><td>현재 부서의 <code>MAX(SALARY)</code></td><td>1개</td><td>단일행</td></tr>
<tr><td>현재 부서의 <code>AVG(SALARY)</code></td><td>1개</td><td>단일행</td></tr>
<tr><td><code>GROUP BY 반</code>으로 반별 최고점 조회</td><td>여러 개</td><td>다중행</td></tr>
<tr><td><code>GROUP BY DEPARTMENT_ID</code>로 조건 만족 부서 조회</td><td>여러 개 가능</td><td>다중행 → IN</td></tr>
</table>

<h3>13. 문제 문장에서 서브쿼리 신호 찾기</h3>
<table>
<tr><th>문제 표현</th><th>먼저 생각할 SELECT</th></tr>
<tr><td>“찬희보다…”</td><td>찬희의 값을 조회</td></tr>
<tr><td>“평균보다…”</td><td><code>AVG()</code>로 기준 평균 조회</td></tr>
<tr><td>“최고 급여와 같은…”</td><td><code>MAX()</code>로 최고 급여 조회</td></tr>
<tr><td>“자기 부서 평균…”</td><td>현재 직원과 같은 부서 조건 + AVG</td></tr>
<tr><td>“각 부서에서 최고…”</td><td>현재 직원 부서 조건 + MAX</td></tr>
<tr><td>“평균 7000 이상인 부서에 속한…”</td><td>먼저 조건 만족 부서ID 목록 조회 → IN</td></tr>
</table>

<h3>14. 서브쿼리 문제 풀이 순서</h3>
<div class="recipe"><b>STEP 1.</b> 비교 기준을 찾기 — 누구보다? 평균보다? 최고값? 어떤 부서?</div>
<div class="recipe"><b>STEP 2.</b> 기준값을 구하는 안쪽 SELECT부터 작성하고 따로 실행하기.</div>
<div class="recipe"><b>STEP 3.</b> 결과 개수 확인 — 1개면 비교 연산자, 여러 개면 수업에서는 IN.</div>
<div class="recipe"><b>STEP 4.</b> “자기 부서 / 같은 반”이면 바깥 별칭과 안쪽 별칭을 연결하기.</div>
<div class="recipe"><b>STEP 5.</b> GROUP BY가 진짜 필요한지 판단 — AVG/MAX가 있다고 무조건 GROUP BY는 아님.</div>
<div class="recipe"><b>STEP 6.</b> JOIN은 테이블 연결, 서브쿼리는 비교 기준 계산, GROUP BY는 그룹별 집계를 담당한다고 역할 나누기.</div>

<h3>15. 자주 틀리는 부분</h3>
<table>
<tr><th>실수</th><th>확인</th></tr>
<tr><td>다중행 결과에 <code>=</code> 사용</td><td>안쪽 SELECT만 실행해 여러 행인지 확인 → IN 필요 여부 확인</td></tr>
<tr><td>자기 부서 문제에서 전체 평균 계산</td><td><code>E2.DEPARTMENT_ID = E.DEPARTMENT_ID</code>가 있는지 확인</td></tr>
<tr><td>AVG가 보이자마자 GROUP BY 추가</td><td>WHERE로 이미 한 부서만 좁혔는지 확인</td></tr>
<tr><td>JOIN 조건 누락</td><td><code>E.DEPARTMENT_ID = D.DEPARTMENT_ID</code> 같은 연결 조건 확인</td></tr>
<tr><td>WHERE와 HAVING 혼동</td><td>개별 행 조건인지, GROUP BY 후 집계 결과 조건인지 구분</td></tr>
</table>

<div class="danger"><b>시험 직전 핵심:</b> 안쪽 SELECT 먼저 → 결과가 1개인지 여러 개인지 → 자기 부서/같은 반이면 바깥 별칭 연결 → 바깥 SELECT 완성.</div>
