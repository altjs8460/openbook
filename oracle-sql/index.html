2. JOIN

공통 컬럼을 기준으로 여러 테이블을 연결합니다.

SELECT E.LAST_NAME, D.DEPARTMENT_NAME
FROM EMPLOYEES E, DEPARTMENTS D
WHERE E.DEPARTMENT_ID = D.DEPARTMENT_ID;
SELECT E.LAST_NAME, D.DEPARTMENT_NAME
FROM EMPLOYEES E
JOIN DEPARTMENTS D
ON E.DEPARTMENT_ID = D.DEPARTMENT_ID;

수업 범위: Oracle JOIN, ANSI JOIN, LEFT/RIGHT/FULL OUTER JOIN, SELF JOIN.

4. 서브쿼리 — 가장 먼저 이해할 것

서브쿼리란? SELECT문 안에 괄호로 들어가는 또 다른 SELECT문. 괄호 안 SELECT가 먼저 실행되고 그 결과를 바깥 SQL이 사용합니다.
문제 표현생각
찬희보다 점수가 낮은찬희 점수를 먼저 구함
평균보다 높은AVG 결과를 먼저 구함
최고 급여와 같은MAX 결과를 먼저 구함
자기 부서 평균현재 직원과 같은 부서만 안쪽에서 계산

수업 예제: 찬희보다 낮은 학생

SELECT 이름, 점수
FROM 반_성적표
WHERE 점수 < (
    SELECT 점수
    FROM 반_성적표
    WHERE 이름 = '찬희'
);
실행내용
① 안쪽찬희 점수 95 조회
② 바깥WHERE 점수 < 95로 동작
③ 결과95보다 낮은 학생 출력
작성 요령: 안쪽 SELECT만 먼저 작성·실행 → 결과 확인 → 바깥 SQL 작성 → 기준값 자리에 안쪽 SELECT를 넣습니다.

5. 단일행 vs 다중행 서브쿼리

구분안쪽 결과수업 기준
단일행1개=, >, <, >=, <=
다중행여러 개IN

다중행 예: 각 반 최고 점수 목록

SELECT 이름, 반, 점수
FROM 반_성적표
WHERE 점수 IN (
    SELECT MAX(점수)
    FROM 반_성적표
    WHERE 점수 IS NOT NULL
    GROUP BY 반
);
안쪽 SELECT만 실행해 여러 행이 나온다면 = 같은 단일 비교 연산자를 그대로 쓰지 말고, 수업에서 배운 IN이 필요한지 확인합니다.

6. “같은 반 / 자기 부서” 패턴

안쪽 SELECT가 바깥에서 현재 검사 중인 행의 값을 참고합니다. 예: B.반 = A.반, E2.DEPARTMENT_ID = E.DEPARTMENT_ID.
SELECT 이름, 반, 점수
FROM 반_성적표 A
WHERE 점수 IS NOT NULL
GROUP BY 이름, 반, 점수
HAVING 점수 = (
    SELECT MAX(점수)
    FROM 반_성적표 B
    WHERE B.반 = A.반
);
별칭의미
A현재 검사 중인 학생
B같은 반의 최고 점수를 구하기 위해 다시 읽는 테이블
B.반 = A.반현재 학생과 같은 반만 비교
이런 형태는 일반적으로 상관 서브쿼리라고 부릅니다. 수업 코드의 동작 이해를 위한 용어 보충입니다.

7. 실습 — 부서별 최고 급여 직원

SELECT E.LAST_NAME, D.DEPARTMENT_NAME, E.SALARY
FROM EMPLOYEES E, DEPARTMENTS D
WHERE E.DEPARTMENT_ID = D.DEPARTMENT_ID
AND E.SALARY = (
    SELECT MAX(E2.SALARY)
    FROM EMPLOYEES E2
    WHERE E2.DEPARTMENT_ID = E.DEPARTMENT_ID
);

E는 현재 직원, E2는 같은 부서 사람들을 다시 조회합니다. 안쪽 MAX는 현재 직원 부서의 최고 급여 1개를 반환합니다.

8. 실습 — 자기 부서 평균보다 많이 받는 직원

SELECT E.LAST_NAME, D.DEPARTMENT_NAME, E.SALARY
FROM EMPLOYEES E, DEPARTMENTS D
WHERE E.DEPARTMENT_ID = D.DEPARTMENT_ID
AND E.SALARY > (
    SELECT AVG(E2.SALARY)
    FROM EMPLOYEES E2
    WHERE E2.DEPARTMENT_ID = E.DEPARTMENT_ID
);
왜 GROUP BY가 없을까? 안쪽 WHERE가 이미 현재 직원과 같은 한 부서만 골라 놓았습니다. 그 행들의 AVG 하나만 계산하면 되므로 여러 부서를 각각 그룹화할 필요가 없습니다. AVG가 있다고 무조건 GROUP BY를 쓰는 것은 아닙니다.

9. 실습 — 부서별 평균 이상 직원 수

SELECT D.DEPARTMENT_NAME, COUNT(*) AS 직원수
FROM EMPLOYEES E, DEPARTMENTS D
WHERE E.DEPARTMENT_ID = D.DEPARTMENT_ID
AND E.SALARY >= (
    SELECT AVG(E2.SALARY)
    FROM EMPLOYEES E2
    WHERE E2.DEPARTMENT_ID = E.DEPARTMENT_ID
)
GROUP BY D.DEPARTMENT_NAME;

① JOIN → ② 직원마다 자기 부서 평균 계산 → ③ 평균 이상만 WHERE에서 남김 → ④ 남은 직원들을 부서별 GROUP BY → ⑤ COUNT.

10. 실습 — 평균 급여 7000 이상인 부서의 직원

SELECT E.LAST_NAME, D.DEPARTMENT_NAME, E.SALARY
FROM EMPLOYEES E, DEPARTMENTS D
WHERE E.DEPARTMENT_ID = D.DEPARTMENT_ID
AND E.DEPARTMENT_ID IN (
    SELECT DEPARTMENT_ID
    FROM EMPLOYEES
    WHERE DEPARTMENT_ID IS NOT NULL
    GROUP BY DEPARTMENT_ID
    HAVING AVG(SALARY) >= 7000
);
부분이유
GROUP BY DEPARTMENT_ID부서별 평균 계산
HAVING AVG(SALARY) >= 7000집계 결과에 조건
IN조건을 만족하는 부서ID가 여러 개일 수 있음

11. 서브쿼리 문제 풀이 공식

STEP 1. 문제에서 비교 기준을 찾기 — 누구보다? 평균보다? 최고값? 어떤 부서?
STEP 2. 기준값만 구하는 안쪽 SELECT를 먼저 작성하고 단독 실행.
STEP 3. 결과 개수 확인 — 1개면 비교 연산자, 여러 개면 수업에서는 IN.
STEP 4. “자기 부서/같은 반”이면 바깥 별칭 연결 — E2.DEPARTMENT_ID = E.DEPARTMENT_ID.
STEP 5. GROUP BY는 AVG/MAX가 있다는 이유만으로 넣지 말고 여러 그룹별 결과가 필요한지 판단.
STEP 6. JOIN은 테이블 연결, 서브쿼리는 비교 기준 계산, GROUP BY는 그룹 집계를 담당한다고 역할을 분리.
시험 직전 한 줄: 안쪽 SELECT 먼저 → 결과 1개/여러 개 → 자기 부서/같은 반이면 바깥 별칭 연결 → 바깥 SELECT.
