1. Node.js와 싱글 스레드

Node.js는 브라우저 밖에서 JavaScript를 실행하는 환경이에요. 서버, 파일, 네트워크 프로그램을 만들 때 사용할 수 있어요.

싱글 스레드는 JavaScript를 실행하는 기본 흐름이 하나라는 뜻이에요. 파일·네트워크 결과를 기다리는 동안에는 다른 요청 처리를 진행하게 넘길 수 있어요.

이벤트 루프는 비동기 작업이 완료되었을 때 등록한 콜백을 실행하도록 작업 순서를 관리해요. 파일 I/O·네트워크 I/O는 운영체제나 보조 작업의 도움을 받을 수 있어요.

답안 문장: Node.js는 JavaScript 실행 흐름이 기본적으로 하나인 싱글 스레드 환경이다. 비동기 I/O와 이벤트 루프를 이용해 대기 중에도 다른 요청을 처리한다. 다만 오래 걸리는 CPU 계산은 메인 스레드를 차지해 전체 처리를 지연시킬 수 있다.

2. 동기·비동기와 Blocking·Non-Blocking

방식뜻장점단점
동기앞 작업 결과를 기다린 뒤 다음 작업순서가 명확하고 이해하기 쉬움대기 시간 동안 뒤 작업이 늦어질 수 있음
비동기작업 결과를 기다리는 중에도 다른 작업대기 시간을 다른 처리에 활용실행 순서·오류 관리가 복잡
Blocking작업이 끝날 때까지 현재 흐름이 멈춰 기다림설계가 단순하고 직관적시간 효율이 낮아질 수 있음
Non-Blocking기다리는 동안 제어를 돌려 다른 작업 가능다른 작업을 계속 처리 가능구조가 복잡해질 수 있음
동기/비동기는 결과를 언제 이어서 처리하는지, Blocking/Non-Blocking은 기다리는 동안 현재 흐름이 막히는지를 설명해요.
// 콜백: 나중에 실행할 함수를 넘김
setTimeout(function () {
  console.log('타이머 작업');
}, 0);

// Promise: 성공과 오류에 다음 작업을 연결
fetch('/data')
  .then(function (response) { return response.json(); })
  .then(function (data) { console.log(data); })
  .catch(function (error) { console.error(error); });
  • setTimeout(함수, 시간)은 나중에 실행할 함수를 예약해요.
  • .then()은 Promise 성공 뒤 처리, .catch()는 오류 처리를 연결해요.
async function getData() {
  try {
    const response = await fetch('/data');
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error(error);
  }
}
getData();
  • async 함수 안에서 await를 쓸 수 있어요.
  • await는 해당 함수의 다음 줄이 결과를 기다리게 해요. 서버의 모든 코드가 멈추는 것은 아니에요.
답안 요약: 동기는 앞 작업이 끝나야 다음 작업을 해 순서가 단순하다. 비동기는 기다리는 동안 다른 작업을 해 효율적일 수 있지만 결과와 오류를 관리해야 한다.

3. HTTP 요청·응답, GET·POST

클라이언트는 요청(Request)을 보내고 서버는 처리 결과를 응답(Response)해요.

방식목적Express에서 값 읽기
GET조회req.query
POST폼 데이터 등 전송파서 등록 후 req.body
res.writeHead(200, {
  'Content-Type': 'text/html; charset=utf-8'
});
res.write('<h1>첫번째 값: ' + qs.num1 + '</h1>');
res.end();
  • writeHead(200, ...)는 성공 상태와 응답 종류·한글 인코딩을 정해요.
  • res.write()는 응답에 내용을 더하고, res.end()는 응답을 마쳐요.
  • 폼 숫자는 문자열이므로 계산 전에 숫자로 바꿔요. Number(qs.num1) 또는 parseInt(qs.num1)를 사용해요.
  • 변수 이름이 틀리거나 값이 없으면 undefined가 될 수 있고, 이를 숫자로 바꾸면 NaN이 나올 수 있어요.
보안: POST는 주소에 값이 보이지 않을 뿐 자동 암호화가 아니에요. 실제 비밀번호는 HTTPS로 보내고 해시해서 저장해야 해요.
답안 문장: GET은 보통 조회에 사용하고 값이 URL의 쿼리로 전달되어 req.query에서 읽는다. POST는 요청 본문으로 값이 전달되어 body parser 등록 후 req.body에서 읽는다.

4. Express·미들웨어·라우터

const express = require('express');
const app = express();

app.use(express.urlencoded({ extended: true }));
app.use(express.static('public'));

app.get('/', (req, res) => {
  res.sendFile(__dirname + '/public/main.html');
});

app.listen(3000);
  • require('express')는 Express를 가져오고 express()는 앱을 만들어요.
  • express.urlencoded()는 폼 데이터를 req.body로 읽게 해요.
  • express.static('public')은 public 폴더의 HTML·CSS·이미지를 제공해요.
  • app.get('/', ...)은 메인 URL의 GET 요청을 처리해요.
  • req는 요청, res는 응답이에요.
  • __dirname은 현재 JS 파일의 절대 경로예요. res.sendFile()은 파일을 보내고, res.redirect()는 다른 URL로 이동시켜요.
  • app.listen(3000)은 3000번 포트에서 기다려요.

Router 파일로 나누기

// app.js
const userRouter = require('./routes/userRouter');
app.use('/user', userRouter);

// routes/userRouter.js
const express = require('express');
const router = express.Router();
module.exports = router;
  • express.Router()는 라우트를 별도 파일에 모아요.
  • module.exports로 내보낸 라우터를 app.js에서 require()로 불러와요.
  • 앱의 mount 경로와 내부 경로가 이어져요. app.use('/user', userRouter) + router.post('/join') = POST /user/join.
  • 미들웨어와 라우터는 등록한 순서가 중요해요. 폼 파서는 라우트보다 먼저 둬요.
폴더 역할: config는 설정, routes는 주소 처리, views는 화면 템플릿, app.js는 미들웨어·라우터·서버를 연결하는 중심 파일이에요.

5. Nunjucks 템플릿

res.sendFile()은 파일을 그대로 보내고, res.render()는 서버 데이터를 HTML에 넣어 완성된 페이지를 보내요.

const nunjucks = require('nunjucks');
app.set('view engine', 'html');
nunjucks.configure('views', {
  express: app,
  watch: true
});

res.render('main', { name: '김미선' });
  • app.set()은 화면 엔진의 확장자를 HTML로 설정해요.
  • configure('views', ...)는 views 폴더를 템플릿 위치로 설정해요.
  • express: app은 Nunjucks와 Express 앱을 연결해요.
  • watch: true는 개발 중 파일 변경을 감지해 다시 읽어요. 이 기능에 chokidar가 필요해요.
  • res.render('main', { name: '김미선' })은 views/main.html에 name 값을 전달해요.
문법기능닫기
{{ name }}값 출력불필요
{% if 조건 %}조건 표시{% endif %}
{% for x in 배열 %}반복{% endfor %}
{% include 'footer.html' %}다른 파일 포함불필요
{% extends 'main.html' %}공통 틀 상속block은 endblock
{% if know %}
  <h1>{{ know }}님 환영합니다</h1>
{% else %}
  <h1>다시 로그인해주세요</h1>
{% endif %}

서버가 res.render('loginResult', { know: id })로 값을 넘기면 성공 문구를, 값을 넘기지 않으면 다시 로그인 문구를 보여줄 수 있어요.

6. 쿠키·세션

쿠키브라우저에 저장. 다음 요청에 세션 ID를 함께 보냄
세션서버가 로그인 상태 등 사용자별 정보를 기억
session-file-store세션 정보를 파일에 저장. MySQL과 별개
const session = require('express-session');
const fileStore = require('session-file-store')(session);

app.use(session({
  resave: false,
  secret: process.env.SESSION_SECRET || '개발용 키',
  store: new fileStore(),
  saveUninitialized: false,
  cookie: { httpOnly: true }
}));
  • express-session은 세션 미들웨어예요. 라우터보다 먼저 등록해요.
  • resave: false는 바뀌지 않은 세션을 매번 저장하지 않아요.
  • secret은 세션 쿠키 서명에 쓰는 비밀 값이에요. 실제 서비스는 환경 변수로 관리해요.
  • store는 세션 저장소를 파일로 지정해요.
  • saveUninitialized: false는 빈 세션을 저장하지 않아요.
  • cookie.httpOnly는 브라우저 JavaScript가 쿠키를 읽지 못하게 해요.
받은 app.js는 httpOnly를 session 옵션 바깥에 적어 두었어요. 쿠키 옵션으로 적용하려면 위 코드처럼 cookie 안에 넣어요.
답안 문장: 쿠키는 브라우저에 저장되는 값이고, 세션은 서버가 사용자 상태를 기억하는 방식이다. express-session은 세션 데이터를 서버 저장소에 두고, 쿠키에는 보통 세션 ID를 저장한다.

8. 서술형 답안 연습

Node.js란?
Node.js는 브라우저 밖에서 JavaScript를 실행하는 런타임 환경이다. 서버와 파일·네트워크 프로그램을 만들 수 있으며 비동기 I/O와 이벤트 루프로 대기 중에도 다른 요청을 처리한다.
싱글 스레드인데 여러 요청을 처리하는 이유?
JavaScript 실행 흐름은 기본적으로 하나지만, 파일·네트워크 응답은 비동기로 맡길 수 있다. 이벤트 루프가 완료된 작업의 콜백을 실행하므로 기다리는 동안 다른 요청을 처리할 수 있다.
동기와 비동기 차이는?
동기는 앞 작업이 끝난 뒤 다음 작업을 실행해 순서가 명확하다. 비동기는 결과를 기다리는 동안 다른 작업을 실행해 대기 시간을 활용할 수 있지만 결과 순서와 오류 처리가 복잡해진다.
GET과 POST 차이는?
GET은 보통 조회에 사용하고 입력값이 URL의 쿼리 문자열로 전달되어 req.query로 읽는다. POST는 요청 본문에 값이 담기며 본문 파서 등록 후 req.body로 읽는다. POST 자체가 통신을 암호화하지는 않는다.
미들웨어란?
미들웨어는 요청과 응답 사이에서 실행되는 함수다. 폼 파싱, 정적 파일 제공, 세션 확인 등에 사용하고 app.use()로 등록한다. 요청 본문 파서는 라우트보다 먼저 등록해야 한다.
세션과 쿠키 차이는?
쿠키는 브라우저에 저장되는 작은 값이고 세션은 서버가 사용자 상태를 기억하는 방법이다. 세션 ID는 쿠키로 전달되고, 세션 데이터는 서버 저장소에 둔다.
Nunjucks와 정적 HTML 차이는?
정적 HTML은 저장된 파일을 그대로 보낸다. Nunjucks는 서버에서 데이터를 템플릿에 넣어 사용자별 HTML을 만든 뒤 응답한다.
mysql2 설치만 하면 DB 연결이 되나?
아니다. mysql2는 연결용 드라이버다. 접속 정보로 연결 풀이나 연결을 만들고, SQL을 실행해야 실제 DB 작업이 된다.
SQL 물음표 바인딩을 쓰는 이유?
사용자 입력을 SQL 문자열에 직접 이어 붙이지 않고 별도 값으로 전달하기 위해서다. 값과 SQL을 분리해 입력값이 SQL 문법으로 해석되는 위험을 줄인다.

9. 객관식으로 개념 확인하기

먼저 답을 생각한 뒤 항목을 눌러 정답과 이유를 확인해요.

1. Node.js에 대한 설명으로 알맞은 것은?
정답: 브라우저 밖에서 JavaScript를 실행하는 런타임 환경
Node.js는 JavaScript 실행 환경이며, 서버나 파일·네트워크 프로그램을 만들 수 있어요.
2. 싱글 스레드인 Node.js가 I/O 대기 중 다른 요청을 처리할 수 있는 이유는?
정답: 비동기 I/O와 이벤트 루프를 사용하기 때문
대기 작업의 결과를 기다리는 동안 실행 흐름을 다른 작업에 넘기고, 완료된 작업은 이벤트 루프가 이어서 처리해요.
3. 동기와 비동기의 차이를 가장 잘 설명한 것은?
정답: 결과를 이어서 처리하는 방식과 시점의 차이
동기는 앞 작업 결과를 받은 뒤 다음 작업을 하고, 비동기는 기다리는 동안 다른 작업을 진행할 수 있어요.
4. GET 요청의 쿼리 값은 Express에서 어디로 읽을까?
정답: req.query
예를 들어 /search?word=node의 word 값은 req.query.word로 읽어요.
5. POST 폼 값을 req.body에서 읽기 전에 필요한 것은?
정답: express.urlencoded() 같은 본문 파서 미들웨어 등록
폼의 name 값도 확인하고, 파서는 라우트보다 먼저 등록해야 해요.
6. app.use('/user', userRouter)와 router.post('/join')이 연결되면 주소는?
정답: POST /user/join
앱에 연결한 기본 경로 뒤에 라우터 내부 경로를 붙여요.
7. res.sendFile()과 res.render()의 차이는?
정답: 파일 그대로 보내기와 데이터를 템플릿에 넣어 보내기의 차이
sendFile()은 정적 파일을 보내고, render()는 서버 데이터를 HTML 템플릿에 넣어 결과 페이지를 만들어요.
8. 쿠키와 세션의 설명으로 알맞은 것은?
정답: 쿠키는 브라우저에, 세션 데이터는 보통 서버 저장소에 둔다
브라우저는 쿠키로 세션 ID를 보내고, 서버는 그 ID에 해당하는 사용자 상태를 확인해요.
9. mysql2 설치 후 바로 가능한 것은?
정답: 아직 DB 연결은 되지 않는다
MySQL 실행, 접속 정보, 연결 풀 또는 연결 생성, SQL 실행이 필요해요.
10. SQL의 ? 바인딩을 사용하는 주된 이유는?
정답: SQL 문장과 사용자 입력값을 분리해 안전하게 전달하기 위해
값을 SQL 문자열에 직접 이어 붙이는 방식보다 SQL 삽입 공격 위험을 줄일 수 있어요.

12. 모듈 설치 명령과 역할

각 명령은 해당 프로젝트의 package.json이 있는 폴더에서 실행해요.

# 접속 IP 확인 실습
npm install request-ip

# Express 서버 프로젝트
npm install express

# body-parser를 직접 require하는 코드
npm install body-parser

# Nunjucks 실습
npm install express nunjucks chokidar

# 5.DB 프로젝트에 기록된 패키지
npm install express nunjucks chokidar express-session session-file-store mysql2

# nodemon을 컴퓨터 전체에 설치
npm i nodemon -g
모듈쓰는 목적

request-ip요청에서 접속 IP 확인
body-parser폼 본문 읽기. Express의 express.urlencoded()를 쓰면 별도 설치 불필요
nunjucks데이터를 넣어 HTML 템플릿 생성
chokidar파일 변경 감지. Nunjucks watch 기능에 사용
express-session세션으로 로그인 상태 등 저장
session-file-store세션 데이터를 파일로 저장
mysql2Node.js와 MySQL 연결에 쓰는 드라이버
nodemon -g파일 변경 시 서버 재시작. -g는 global, 컴퓨터 전체 설치
  • npm i는 npm install의 짧은 명령이에요.
  • 프로젝트에 설치하면 node_modules에 파일이 들어가고 package.json에 패키지가 기록돼요. package-lock.json에는 세부 버전이 기록돼요.
  • 전역 nodemon은 프로젝트 package.json에 기록되지 않아요.

13. 5.DB 예상 실습: 진행 순서

시험 대비 예시 실제 시험문제는 아직 확인되지 않았어요. 받은 폴더의 회원 메뉴를 바탕으로 예상 흐름을 정리했어요.

  1. 수업에서 정한 DB명·테이블명·컬럼명을 먼저 확인한다.
  2. MySQL에서 DB와 회원 테이블을 준비한다.
  3. config/db.js에서 연결 풀을 만든다.
  4. app.js에서 폼 파서 → Nunjucks → 세션 → 라우터를 연결한다.
  5. userRouter.js에서 req.body를 읽고 쿼리를 실행한다.
  6. 조회 결과를 화면에 전달하거나 로그인 정보를 세션에 저장한다.
  7. 성공·실패 화면을 각각 확인한다.
중요: 아래 예시는 공부용이에요. 시험에서는 선생님이 준 테이블 이름, 컬럼명, 라우트 주소를 그대로 따라야 해요.

14. DB 연결 설정 예시

예시 위치: config/db.js. DB 이름·계정·비밀번호는 실제 환경 값으로 바꿔요.

const mysql = require('mysql2/promise');

const pool = mysql.createPool({
  host: 'localhost',
  user: 'root',
  password: '내 비밀번호',
  database: 'node_db',
  waitForConnections: true,
  connectionLimit: 10
});

module.exports = pool;
  • mysql2/promise는 async/await로 DB 작업을 하게 해요.
  • createPool()은 여러 요청이 연결을 재사용하도록 연결 풀을 만들어요.
  • host/user/password/database는 MySQL 접속 정보를 지정해요.
  • waitForConnections와 connectionLimit은 연결 풀의 대기와 최대 연결 수를 정해요.
  • module.exports로 pool을 내보내 라우터에서 불러와요.
DB 비밀번호를 공개 GitHub에 올리면 안 돼요. 위 값은 예시 자리 표시자예요.

15. 회원 처리 코드 패턴

공통 준비: app.js에서 userRouter를 불러와 app.use('/user', userRouter)로 연결하고, userRouter.js에서는 express.Router()와 DB pool을 가져와요. 그러면 router.post('/join')의 최종 주소는 POST /user/join이에요.

회원가입: INSERT
router.post('/join', async (req, res, next) => {
  try {
    const { id, pw, nick } = req.body;
    await db.execute(
      'INSERT INTO users (login_id, password, nick) VALUES (?, ?, ?)',
      [id, pw, nick]
    );
    res.redirect('/login');
  } catch (error) {
    next(error);
  }
});
  • POST 라우트가 회원가입 요청을 받아요.
  • req.body에서 폼 입력값을 꺼내요. 폼 input의 name과 키가 같아야 해요.
  • execute는 SQL을 실행해요. ? 자리와 값 배열을 같은 순서로 맞춰요.
  • 성공하면 로그인으로 이동하고, 오류는 next(error)로 넘겨요.
로그인: SELECT + 세션
router.post('/login', async (req, res, next) => {
  try {
    const { id, pw } = req.body;
    const [rows] = await db.execute(
      'SELECT login_id, nick FROM users WHERE login_id = ? AND password = ?',
      [id, pw]
    );
    if (rows.length > 0) {
      req.session.user = { id: rows[0].login_id, nick: rows[0].nick };
      res.redirect('/');
    } else {
      res.render('login', { error: '로그인 정보를 확인하세요' });
    }
  } catch (error) {
    next(error);
  }
});
  • SELECT 결과의 rows 배열을 받아요. 1개 이상이면 일치하는 회원이 있다는 뜻이에요.
  • 로그인 성공 시 사용자 식별 정보를 req.session에 저장해요.
  • 실제 서비스는 비밀번호를 평문 저장·비교하지 않고 해시해서 확인해요.
로그인 검사 미들웨어
function checkLogin(req, res, next) {
  if (!req.session.user) {
    return res.redirect('/login');
  }
  next();
}

router.get('/update', checkLogin, (req, res) => {
  res.render('update', { user: req.session.user });
});
  • 세션 사용자가 없으면 로그인으로 이동해요.
  • 로그인 상태면 next()로 다음 처리 단계에 넘겨요.
  • 보호할 라우트에서 checkLogin을 먼저 실행해요.
회원정보 수정: UPDATE
router.post('/update', checkLogin, async (req, res, next) => {
  try {
    const { nick } = req.body;
    const id = req.session.user.id;
    await db.execute(
      'UPDATE users SET nick = ? WHERE login_id = ?',
      [nick, id]
    );
    req.session.user.nick = nick;
    res.redirect('/');
  } catch (error) {
    next(error);
  }
});
  • 수정할 값은 req.body에서 읽어요.
  • 수정 대상 id는 폼이 아니라 로그인 세션에서 가져와요.
  • UPDATE 물음표 순서와 값 배열 순서를 맞춰요.
회원탈퇴: DELETE와 세션 종료
router.post('/delete', checkLogin, async (req, res, next) => {
  try {
    const id = req.session.user.id;
    await db.execute(
      'DELETE FROM users WHERE login_id = ?',
      [id]
    );
    req.session.destroy(() => res.redirect('/'));
  } catch (error) {
    next(error);
  }
});
  • 현재 로그인한 사람을 세션에서 확인해 DB에서 삭제해요.
  • DB 삭제 후 destroy()로 로그인 세션을 끝내요.
  • 실제 서비스는 삭제 전 확인 절차와 관련 자료 처리도 필요해요.
